1. ECOSYSTEM ARCHITECTURE & SYSTEM OVERVIEW
================================================================================
TravelBuddy is an enterprise-grade smart tourism and safety management platform 
designed to protect tourists, automate trip planning, solve multi-stop travel 
logistics, detect falls/impacts via wearable hardware, enforce geo-fenced danger 
zones with audible sirens, and provide real-time coordination with Police Command 
and Hotel Partners.

The ecosystem connects 6 major subsystems:
- Central Backend REST API (Node.js, Express, PostgreSQL with UUIDs & JSONB)
- Flutter Mobile Application (Cross-Platform Android/iOS with Impeller engine)
- Police Emergency Command Dashboard (React 19, Vite, Leaflet)
- Hotel Partner Portal (React 19, Vite, Guest UID Verification)
- Tourist Web Client (HTML5, Vanilla JS, AI Itinerary Planner & TSP Optimizer)
- IoT Wearable Node (ESP32 Microcontroller + MPU-6050 6-Axis IMU Sensor)
- WhatsApp Tourism Bot (Meta Cloud Graph API with webhook deduplication)

2. CENTRAL BACKEND API (EXPRESS / NODE.JS) - ALL CONTROLLERS & ENDPOINTS
================================================================================
Server Entry: backend/src/server.js
Port: 5000 (Default: http://0.0.0.0:5000)
Core Middleware:
- helmet: Cross-Origin Resource Policy disabled for open media access.
- express.json: 5MB payload limit for base64 media & complex itineraries.
- express.urlencoded: 1MB payload limit for URL-encoded submissions.
- express-rate-limit: Global limiter (300 requests per 15-minute window per IP).
- cors: Dynamic origin whitelist with open access for mobile and dev clients.

API Controller & Endpoint Reference:
--------------------------------------------------------------------------------

A. Authentication Controller (backend/src/controllers/authController.js)
   - POST /api/auth/register
     * Input: { email, password, full_name, phone_number, nationality, emergency_notes }
     * Generates auto-formatted unique Tourist UID (e.g., TB-IND-2026-A1B2).
     * Hashes password using bcrypt (10 rounds).
     * Returns JWT bearer token + full user payload.
   - POST /api/auth/login
     * Input: { email, password }
     * Validates credentials, updates last_login timestamp, issues JWT.
   - GET /api/auth/me
     * Input: Bearer JWT header.
     * Returns current user identity, profile, and Tourist UID.

B. Profile Controller (backend/src/controllers/profileController.js)
   - GET /api/profile
     * Retrieves tourist details, blood group, medical alerts, dietary notes.
   - PUT /api/profile
     * Updates tourist medical alerts, emergency contacts summary, nationality.

C. Trip Controller (backend/src/controllers/tripController.js)
   - GET /api/trips
     * Retrieves all trips belonging to authenticated tourist.
   - POST /api/trips
     * Creates new trip with destination, start_date, end_date, total_budget, currency,
       and complete JSONB itinerary tree (days, attractions, activities, costs).
   - GET /api/trips/:id
     * Returns granular itinerary details for a single trip.
   - PUT /api/trips/:id
     * Updates trip itinerary or status (PLANNED, ONGOING, COMPLETED).
   - DELETE /api/trips/:id
     * Deletes trip record and cascading assets.

D. Hotel Stay Controller (backend/src/controllers/hotelStayController.js)
   - GET /api/hotel-stays
     * Returns all hotel stays for the logged-in tourist.
   - POST /api/hotel-stays
     * Creates booking/stay link with hotel_id, check_in_date, check_out_date, room_number.
   - GET /api/hotel-stays/:id
     * Fetches details, hotel address, contact phone, and amenities.

E. Emergency Contact Controller (backend/src/controllers/emergencyContactController.js)
   - GET /api/emergency-contacts
     * Returns ordered list of emergency contacts (ranked by priority 1..5).
   - POST /api/emergency-contacts
     * Input: { contact_name, relationship, phone_number, email, priority_order }
   - PUT /api/emergency-contacts/:id
     * Updates contact details or priority ranking.
   - DELETE /api/emergency-contacts/:id

F. SOS Controller (backend/src/controllers/sosController.js)
   - POST /api/sos/trigger
     * Input: { latitude, longitude, altitude, battery_level, emergency_type, notes }
     * Creates ACTIVE incident in `sos_incidents`.
     * Logs initial trigger event in `sos_events`.
     * Alerts police dashboard instantly.
   - GET /api/sos/active
     * Checks if current user has an ongoing active SOS incident.
   - POST /api/sos/resolve
     * Marks tourist incident as RESOLVED.

G. Location Controller (backend/src/controllers/locationController.js)
   - POST /api/locations/update
     * Input: { latitude, longitude, altitude, speed, heading, accuracy }
     * Inserts GPS breadcrumb into `locations` table.
     * Evaluates location against all active restricted zones using Haversine algorithm.
     * If breach occurs: records breach in `geofence_breaches` and returns { in_danger_zone: true, play_siren: true, zone: {...} }.

H. Geofence Controller (backend/src/controllers/geofenceController.js)
   - GET /api/geofence/zones
     * Returns list of all active restricted danger sectors with center coordinates,
       radius (meters), threat severity, and advisory messages.
   - POST /api/geofence/check
     * Explicitly calculates distance of a coordinate pair to all restricted zones.

I. IoT Telemetry Controller (backend/src/controllers/iotController.js)
   - POST /api/iot/telemetry
     * Ingests ESP32 telemetry: { device_id, user_id, ax, ay, az, gx, gy, gz, total_accel, pitch, roll, is_fall_detected, latitude, longitude, battery_pct }.

4. GEOFENCING, RESTRICTED DANGER ZONES & PHONE SIREN SUBSYSTEM
================================================================================
A. Spherical Haversine Perimeter Math
   Let (phi1, lambda1) = user GPS coordinate, (phi2, lambda2) = zone center coordinate.
   dphi = (phi2 - phi1) in radians
   dlambda = (lambda2 - lambda1) in radians
   a = sin^2(dphi / 2) + cos(phi1) * cos(phi2) * sin^2(dlambda / 2)
   c = 2 * atan2(sqrt(a), sqrt(1 - a))
   distance = R * c (where R = 6,371,000 meters)

   Breach Condition: distance <= zone.radius_meters
   Penetration Depth = zone.radius_meters - distance

B. Pre-configured Dangerous Sectors:
   1. Ganga High-Current Rapids (Rishikesh): Lat 30.1312, Lng 78.3256, Radius: 450m [CRITICAL]
   2. Neelkanth Cliffside Landslide Hazard: Lat 30.1589, Lng 78.3412, Radius: 600m [HIGH]
   3. Military Perimeter Sector 7: Lat 30.1120, Lng 78.2910, Radius: 800m [RESTRICTED]
   4. Bandra Coastal Tide Surge: Lat 19.0435, Lng 72.8195, Radius: 500m [HIGH]

C. Phone Warning Siren & UI Alerting (mobile/lib/services/siren_service.dart)
   - Implements synthesized dual-frequency emergency frequency loop (880Hz / 440Hz).
   - Uses `audioplayers` with max stream volume on STREAM_ALARM channel.
   - Displays full-screen red warning modal with danger zone title, severity badge,
     and "Silence Siren & Acknowledge" button.
   - Automatically synchronizes breach event to police threat feed.

5. IOT WEARABLE SENSOR HARDWARE SUBSYSTEM (ESP32 + MPU6050)
================================================================================
Hardware Platform: ESP32 Dev Module + MPU-6050 6-Axis Motion Tracking Sensor (I2C)
Firmware File: iot/esp32_mpu6050_geofence_node.ino

A. Sensor Sampling & Kinematic Vectors:
   - Accelerometer: ax, ay, az (±2g range, 16384 LSB/g)
   - Gyroscope: gx, gy, gz (±250°/s range, 131 LSB/(°/s))
   - Total Acceleration Vector: A = sqrt(ax^2 + ay^2 + az^2)
   - Pitch Angle: atan2(ay, sqrt(ax^2 + az^2)) * (180 / PI)
   - Roll Angle: atan2(-ax, az) * (180 / PI)

B. Anomaly & Fall Detection Algorithm:
   - Free-fall Phase: A < 0.35g sustained for >= 150 milliseconds.
   - Impact Phase: A > 2.80g sudden spike immediately following freefall.
   - Posture Inactivity: User orientation remains static in tilted/lying plane.
   - Immediate HTTP POST telemetry transmission to /api/iot/telemetry with is_fall_detected = true.

C. Edge Hardware Warning:
   - Onboard piezo buzzer on GPIO pin 23 emits 2.4kHz pulsed tones if backend returns
     `{ geofence_breach: true, play_siren: true }` in HTTP response header/payload.

   - Live destination risk index calculation.
   - Highlights restricted sectors in translucent red circles with threat tooltips and advisories.
7. Responsive Header & Navigation Architecture:
   - Fluid responsive layout preventing text/logo overlap across all zoom scales (100%, 125%, 150%) and screen resolutions (1080p, 1366x768, 1440x900, 1536x864, 4K).
   - Adaptive text shortening (`IoT Destination Monitor` -> `IoT Monitor`) and mobile drawer slide-out menu.

10. AI ENGINE & ROUTE OPTIMIZATION ALGORITHMS
================================================================================
A. Groq Llama-3 Itinerary Generator:
   - Endpoint: POST /api/ai/generate-itinerary
   - Model: Llama-3-70b-versatile via Groq Cloud API.
   - Strict JSON Schema output enforcing structured day objects, time slots,
     coordinates, estimated costs in local currency, and local safety tips.

B. OSRM Multi-Stop TSP Route Optimizer:
   - Endpoint: POST /api/routes/optimize
   - Computes distance/duration matrix across all selected waypoints.
   - Executes Nearest-Neighbor with 2-Opt local search to find optimal visiting order.
   - Computes estimated transit fuel / taxi costs.

Location: backend/src/controllers/whatsappController.js
Webhook: POST /api/whatsapp/webhook

Features:
