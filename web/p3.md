# 4. Main objective

The system should answer:

> **“Can I afford to travel from my starting location to my destination and return within my entered budget? If yes, which available route is the best and uses the least possible budget?”**

Example:

```text id="4p7z8n"
Starting location: Delhi
Destination: Rishikesh
User budget: ₹1,000
```

The system should:

1. Calculate the distance.
2. Find available route alternatives.
3. Calculate the estimated cost of each route.
4. Calculate the return journey cost.
5. Compare all routes.
6. Filter routes that exceed the budget.
7. Select the best feasible route.
8. Show whether the trip is possible.

---

# 5. Important: Use the correct algorithms

Do not use TSP as the primary algorithm for this feature.

### Recommended algorithm architecture

```text id="9p4k2m"
Routing API
    ↓
Route Alternatives
    ↓
Cost Calculation
    ↓
Budget Filtering
    ↓
Greedy / Sorting
    ↓
Weighted Scoring
    ↓
Best Feasible Route
```

### Algorithm 1: Routing API

Use a routing API to calculate:

* Distance
* Travel time
* Route alternatives
* Route geometry where available
* Toll information where available

If the project already has a routing API, reuse it.

If no routing API is available, create a clean service interface so a real routing API can be connected later.

Do not hardcode one universal route.

---

### Algorithm 2: Greedy / Sorting

Use a greedy or sorting-based approach to select the **cheapest feasible route**.

Example:

```text id="f4r8mc"
Route A: ₹1,000
Route B: ₹1,300
Route C: ₹1,100

User budget: ₹1,200
```

Filter:

```text id="1a5z7v"
Route A → Feasible
Route B → Not feasible
Route C → Feasible
```

Then select:

```text id="r8q2ny"
Minimum Budget Route = Route A
```

This is the correct approach for the current problem.

---

### Algorithm 3: Weighted Scoring

Use weighted scoring to select the **Best Overall Route**.

The score should consider:

* Cost
* Travel time
* Route quality
* Toll cost
* User preferences

For a budget-focused user:

```text id="7m3k9p"
Cost = highest priority
```

For a balanced user:

```text id="2n8q4v"
Cost + Time + Quality = balanced priority
```

For a comfort-focused user:

```text id="6p1w8c"
Comfort + Time + Quality = higher priority
```

Make the weights configurable.

Do not use random scores.

---

# 6. When to use TSP

TSP should not be used for the current Delhi → Rishikesh route selection problem.

Use TSP later when the user enters multiple destinations, for example:

```text id="3k8m2p"
Delhi
    ↓
Rishikesh
    ↓
Haridwar
    ↓
Mussoorie
    ↓
Delhi
```

Then the problem becomes:

> **“What is the best order to visit all these destinations while minimizing total travel cost or distance?”**

That is where TSP or a similar multi-stop route optimization algorithm becomes useful.

For now, implement only:

```text id="7q2m9x"
Origin → Destination → Origin
```

# 12. Best feasible route selection

First filter routes:

```js id="s7p3nk"
const feasibleRoutes = routes.filter(
  route => route.roundTripCost <= userBudget
);
```

Then rank the feasible routes.

### Minimum Budget Route

Select the route with the lowest estimated round-trip cost.

```js id="a2m8vq"
const minimumBudgetRoute = feasibleRoutes.sort(
  (a, b) => a.roundTripCost - b.roundTripCost
)[0];
```

### Best Overall Route

Select the route with the best weighted score.

Example:

```text id="k8q4mw"
Route Score =
Cost Score
+ Time Score
+ Quality Score
+ Preference Match Score
```

The scoring weights should be configurable.
